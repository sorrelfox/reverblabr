# Internationalization

Reverblabr is translatable from the first line of interface code. Version 1.0 ships in English only, but adding a language must be a translation job with no code changes. This page covers how to mark strings, how numbers and dates are shown and stored, how engine errors reach the user, and the tools that check all of it.

## Marking strings

All user-visible text goes through **KI18n**, with the application's translation domain `reverblabr`. The GUI targets define `TRANSLATION_DOMAIN`, so every call uses that catalog.

| Where | How |
|---|---|
| C++ | `i18nc("@label", "Level")` |
| QML | `import org.kde.ki18n`, then `KI18n.i18nc("@label", "Level")` |
| Plurals | `i18ncp("@info", "%1 file", "%1 files", count)`, and `KI18n.i18ncp(...)` in QML |
| Tables built before translation runs (block names, error messages) | `kli18nc("@info", "…")`, the lazy form; convert with `toString()` or `KLocalizedString` when shown |

- **Always give a context.** It uses KDE's markers, so translators know where the text appears:

  | Marker | Use |
  |---|---|
  | `@title`, `@title:window` | window and page titles |
  | `@action:button`, `@action:inmenu` | buttons, menu items |
  | `@label` | labels |
  | `@info`, `@info:tooltip`, `@info:status` | messages, tooltips, status text |
  | `@item` | list and combo-box items |

  Add detail after the marker when a word is ambiguous: `i18nc("@label block name", "Pan")`.
- **Use whole sentences with placeholders.** Never build a sentence by concatenating pieces: `i18nc("@info", "Recording %1 finished", name)`, not `"Recording " + name + " finished"`. Placeholders let translators reorder words.
- **Keep a message on one line in QML.** `"…first half " + "second half…"` works when it runs, but xgettext reads QML with its C++ parser and extracts only the first piece, so the catalog's message never matches and the words are never translated. The lint flags a string continued with `+`.
- **Leave room.** Translations are often 30–40 % longer than English. Let text wrap in panels (a label column: `wrapMode: Text.Wrap` with `maximumLineCount: 2`), let a number's readout grow to its text (`Math.max(fixed, implicitWidth)`), and in places of a fixed size (a tile's face, a panel's header) use `ElidedLabel`, which elides and shows the whole line in a tooltip. The pseudo-locale check below finds what doesn't fit.
- **No text in images.** Draw text as a label over an icon.
- **Translator comments.** A C++ or QML comment starting with `i18n:` directly above the call ends up in the catalog as a note for translators.

## Words the daemon says

The desktop notifications are sent by the window and, while no window is open, by the daemon, which has no KDE Frameworks ([ADR-0017](adr/0017-engine-daemon.md)). So their words live in the KDE-free library `notify/`, marked with `RB_I18NC(context, text)` instead of `i18nc`, and looked up by `rb::notify::translate()` with plain gettext, in the same `reverblabr` catalog and under the same context KI18n uses. xgettext is given the keyword `RB_I18NC:1c,2`. The event names in `notify/reverblabr.notifyrc`, which System Settings lists, are translated with the desktop entry's; see below. What KRunner shows of the sessions (`daemon/sessionrunner.cpp`) is said by the daemon too, and marked and looked up the same way.

**The words the desktop shows before Reverblabr runs** have a catalog of their own, `reverblabr-data`: the desktop entry's name, comment, keywords and actions, the notification events System Settings lists, the name and comment KRunner's settings list for the runner, and the AppStream data a software centre shows. They are not KI18n calls, so `Messages.sh` extracts them with xgettext's own rules (its Desktop parser for `app/io.github.reverblabr.Reverblabr.desktop`, `notify/reverblabr.notifyrc` and `daemon/io.github.reverblabr.Runner.desktop`, its AppStream rules for the metainfo) into `reverblabr-data.pot`. The build merges each `po/<language>/reverblabr-data.po` back into the copies it installs (`cmake/RbTranslateDataFile.cmake`, one language at a time with `msgfmt --desktop` or `msgfmt --xml`); with no translations the installed file is the one in the tree. `i18n.data-translations` extracts the template, merges a made-up German catalog through the same script, and checks all four files come out translated, and that the desktop entry and the AppStream data still pass `desktop-file-validate` and `appstreamcli validate`.

## Numbers, units, dates and stored data

- **Show values in the user's locale.** Format numbers, dates and times with `QLocale` (for example `locale.toString(value, 'f', 1)`) and durations with `KFormat::formatDuration()`. Put units inside the translated string, `i18nc("@label frequency", "%1 kHz", value)`, so each language can choose its own spacing and order.
- **Store data without locale.** Sessions, presets and settings always use `.` as the decimal separator and ISO 8601 dates, whatever the user's locale. Never write a `QLocale`-formatted number to a file.
- **Default file names** use ISO dates (`2026-09-13 09-02`), so they sort correctly and stay portable.

## Errors from the engine

The engine never produces user-visible text. It reports an error as `{code, args}`.

1. **The engine declares every code** in [`engine/core/errorcodes.h`](../engine/core/errorcodes.h): an enumerator, the stable name (for example `graph.cycle`), and the names of its arguments.
2. **The GUI translates it.** [`app/errormessages.cpp`](../app/errormessages.cpp) maps each code to a translated message; `%1`, `%2` and so on are the arguments in the order the engine declares them. `rb::app::errorMessage(code, args)` returns the finished text. An unknown code gets a generic message that names it.
3. **Unit tests keep the two sides in step.** The build fails if the enum and the code table disagree. The tests fail if:
   - a code has no message
   - a message has no code
   - a message's placeholders don't match the declared arguments

To add an error, add the enumerator and its row in `errorcodes.h`, then the message in `errormessages.cpp`.

## Tools

| Task | Command |
|---|---|
| Regenerate the templates `po/reverblabr.pot` and `po/reverblabr-ctl.pot` (not committed) | `cmake --build --preset debug --target extract-messages` |
| Check for untranslated interface strings | `tools/lint-i18n.py app` |
| Render the key screens in the pseudo-locale | `ctest --preset debug -R i18n.pseudo-locale` |

**The lint** flags string literals in user-visible places that don't go through KI18n: QML properties such as `text:`, `title:`, `placeholderText:`, `ToolTip.text:` and `Accessible.name:`, and C++ setters such as `setText()` and `setWindowTitle()`. It also flags Qt's own `qsTr()` and `tr()`. It accepts:
- literals without letters (`""`, `"•"`)
- entries in [`tools/i18n-lint-allow.txt`](../tools/i18n-lint-allow.txt)
- lines marked with a `no-i18n` comment that gives the reason, for example `// no-i18n: developer overlay`

The lint runs as a test (`i18n.lint-app`), so [the checks before a change goes in](development.md#before-a-change-goes-in) run it, as they run the extraction test (`i18n.extract`).

**Extraction** is driven by [`Messages.sh`](../Messages.sh), which follows KDE's convention, and by [`tools/extract-messages.sh`](../tools/extract-messages.sh). The GUI (`app/`), the desktop notifications (`notify/`), the daemon (`daemon/`) and `reverblabr-ctl` (`ctl/`) are scanned. QML files are read with xgettext's C++ parser, which finds `KI18n.i18nc(...)` calls just like C++ ones.

**`reverblabr-ctl` has a catalog of its own**, `reverblabr-ctl`. It does not link KI18n, so its words go through `ctlTr(context, text)` and `ctlTrn(context, singular, plural, n)` (`ctl/translate.h`), plain gettext with the same context markers, and are extracted into `reverblabr-ctl.pot`. Its `--json` output is never translated.

**The diagnostics bundle is never translated either**: what Copy Diagnostics puts on the clipboard is for whoever answers a bug report, who needs the same words from every reporter. It is built in C++ from plain strings in `app/diagnostics.cpp`; the Diagnostics section around it is translated like the rest of the window.

## The pseudo-locale

The lint reads source lines; it cannot see a unit appended in a JavaScript function or a message the extractor cut short. **The pseudo-locale looks at the screens instead**.

- [`tools/pseudo-locale.py`](../tools/pseudo-locale.py) turns the template into a made-up language, `qps`: every message comes out as `⟦Áççéñtéð téxtẋǿẋǿ⟧`, its letters accented and about 40 % longer, with its placeholders (`%1`, `%session`), markup and accelerators left as they are.
- `reverblabr-pseudo-check` renders the key screens in it, offscreen on the mock engine: the window with one of every block, stopped and running; the block library, Files and Info; every block's settings panel; the main menu and each of its menus; the session dialogs; the Virtual Devices window; the Sessions window; the Recording Inspector. It walks what is drawn and reports:
  - **untranslated:** visible text with letters and no `⟦`;
  - **cut off:** text that elides or is wider than its room, unless a tooltip on it or just around it says the words in full or at more length, which is eliding by design, with nothing lost.
- It runs as four tests, in the application's own style and in the desktop's (they are not the same size), and twice more with a fault put there on purpose (a hard-coded string, a translated one given too little room), which it has to catch.
- The template is extracted afresh on every run, so the check is never stale. The catalog is never installed.
- **Its report and a screenshot of every screen** land in `build/<preset>/tests/i18n/pseudo-<style>/`. Read the screenshots when a finding is not obvious.
- **What it leaves alone:** data (device, application, session and file names, which the mock makes up), a dialog's standard buttons and written-out shortcuts (Qt translates those from its own catalog, which KI18n loads for a real language), and the Recorder's file-name tokens.

## Right to left

Checked by hand before a release, until a right-to-left language is on the way:

```sh
build/debug/bin/reverblabr -reverse
```

- **The chrome mirrors:** the sidebar, the tool bar, a panel's rows (label on the right, control on the left), menus and dialogs.
- **The canvas does not.** Signal flows left to right in every language, as in every audio application; tiles, wires and lanes stay where the person put them.
- Numbers, units and file names stay left to right inside mirrored text.

## String freeze

Before a release, the words stop changing so that translators can finish:

1. **Freeze** two weeks before the release: announce it in an issue on GitHub, and regenerate the templates.
2. **During the freeze**, no new or changed user-visible string lands, except to fix a real error in one (a wrong word, a broken placeholder). Such a change says so in its pull request and in that issue, so translators know to look again.
3. **Code changes go on.** A fix that needs a new string waits for the next version, or goes in with the string marked for the translators, by agreement in that issue.
4. **At the release**, the catalogs are refreshed from the platform and built into the packages.

## Translation platform

Translations open after the 1.0 string freeze, on a hosted Weblate. To set it up:

- **One component per catalog**, `reverblabr` and `reverblabr-ctl`, each fed from its template: Weblate's "gettext PO" format, with the template generated by `tools/extract-messages.sh` and committed to a translations branch, since the templates are not in the main tree.
- **Where translations land:** `po/<language>/reverblabr.po` and `po/<language>/reverblabr-ctl.po`, through pull requests Weblate opens, which go through the same checks as any other.
- **For translators:** the contexts (`@action:button`, `@info:tooltip`) and the `i18n:` comments are their notes, and the pseudo-locale check's screenshots can be uploaded to Weblate and linked to the messages they show.
- **Licence, to decide before opening:** which licence translations are under, stated in the `.po` headers and in `REUSE.toml`, and the same in Weblate's contributor agreement.

## Adding a language

1. `mkdir -p po/de && msginit -i po/reverblabr.pot -l de -o po/de/reverblabr.po`, then translate.
2. Build. `ki18n_install(po)` compiles every `po/<language>/reverblabr.po` and installs it with the application; no code changes are needed.
3. To try a translation from the build tree:

   ```sh
   XDG_DATA_DIRS="$PWD/build/debug:$XDG_DATA_DIRS" LANGUAGE=de build/debug/bin/reverblabr
   ```

   gettext ignores the chosen language when the system locale is `C` or `C.UTF-8`, so this needs a real locale such as `en_US.UTF-8`. Plasma sessions always have one. The catalog test (`i18n.catalog`) skips itself, with a reason, where no such locale is installed.

Translations open after the 1.0 string freeze; see [String freeze](#string-freeze) and [Translation platform](#translation-platform).
