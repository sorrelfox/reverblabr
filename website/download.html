Fedora 44 and 45

reverblabr-@VERSION@-1.fc45.x86_64.rpm reverblabr-@VERSION@-1.fc44.x86_64.rpm
Fedora 45 package Fedora 44 package

The Fedora package has everything: every block, the background engine, Auto Run and timers, KRunner, the panel widget, virtual devices for all users, reverblabr-ctl with its manual page and shell completions, and the handbook.

There is one for each Fedora. Take your Fedora's: a package built for one doesn't start on the other, since each is built against its own release's FFmpeg and Qt. After an upgrade to a newer Fedora, install the newer Fedora's package.

Install

In the folder you saved it in. The command picks your Fedora's file:

sudo dnf install ./reverblabr-@VERSION@-1.fc$(rpm -E %fedora).x86_64.rpm

What it needs comes from Fedora's own repositories. It also recommends openh264, Cisco's H.264 encoder, for the Live Stream block's video; layer-shell-qt, for the windows that float over other programs; and polkit, for the password prompt of devices for all users.

Start

From the application launcher, or with reverblabr in a terminal.

Remove
sudo dnf remove reverblabr

It is tied to Qt 6.11

The window uses parts of Qt that Qt keeps private and changes from one version to the next, so the package requires Qt 6.11's. If your Fedora moves on to Qt 6.12, that requirement can't be met any more, and the package has to be rebuilt. The source RPM on the release page does that, for a newer Qt or for another Fedora release: Installing has the commands.

Ubuntu and Kubuntu 26.04

reverblabr_@VERSION@-1.ubuntu26.04_amd64.deb
Download the Ubuntu package

For Kubuntu 26.04, and for Ubuntu 26.04 with Plasma.

What it lacks, and why

Three parts, because Ubuntu 26.04 doesn't package what they need:

  • CLAP plugins. Ubuntu has no package of the CLAP SDK.
  • VST3 plugins. Ubuntu's VST3 SDK is version 3.7. Reverblabr takes 3.8 or later, the first version under the MIT licence.
  • Speech Denoise, and the voice model that Speech Now, Voice Gauge and Night Level listen with. Ubuntu has no package of RNNoise. Those three blocks listen with Level and rhythm instead, a simpler detector that can be wrong more often.
Install

In the folder you saved it in:

sudo apt install ./reverblabr_@VERSION@-1.ubuntu26.04_amd64.deb

It recommends polkitd, for the password prompt of devices for all users, and qml6-module-org-kde-layershell, for the windows that float over other programs.

Start

From the application launcher, or with reverblabr in a terminal.

Remove
sudo apt purge reverblabr

Like the Debian package, it is tied to the Qt it was built with, here Ubuntu 26.04's: when Ubuntu moves to another Qt, the package has to be rebuilt.

The Flatpak

reverblabr-@VERSION@-x86_64.flatpak
Download the Flatpak

For any other distribution that has Flatpak, or for when you'd like Reverblabr in a sandbox. It runs on KDE's runtime from Flathub, so it doesn't depend on your distribution's libraries. The window, the background engine and the plugins all run in the one sandbox.

What it lacks, and why

  • Auto Run at login, and timers. Both go through your account's systemd, which a sandbox can't reach, and nothing outside the sandbox can start its engine. The Info and Schedule tabs say so.
  • KRunner and the panel widget. Plasma looks for them in folders on your system, not inside a sandbox.
  • Virtual devices for all users. They need a helper that runs as root, which a Flatpak can't install. Devices for your own account work as in a package.
  • The Model block. The ONNX Runtime it needs isn't built into the Flatpak.
  • Plugins installed on your system. They are built against your system's libraries, not the runtime's, so the sandbox doesn't look for them. It finds the plugins Flathub packages as extensions of org.freedesktop.LinuxAudio.Plugins (branch 25.08) instead.
  • The manual page and the shell completions of reverblabr-ctl.
  • The handbook (F1). It is inside the sandbox, where the desktop's help viewer most likely can't read it. The same pages are in the documentation.
  • Coming back after PipeWire restarts. The sandbox keeps the PipeWire socket it started with, and a restarted PipeWire makes a new one, so the Flatpak's engine can't reconnect by itself as a package's does; closing the window doesn't help. If your sessions stay silent after PipeWire restarted, run flatpak kill io.github.reverblabr.Reverblabr, start Reverblabr again and start your sessions again.
Install

For your account, in the folder you saved it in. Flathub has to be one of your remotes, because the runtime, org.kde.Platform 6.11, comes from there:

flatpak remote-add --user --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
flatpak install --user ./reverblabr-@VERSION@-x86_64.flatpak

Flathub's plugins don't come with the Flatpak. Install the ones you want, LSP's for example, and Look for plugins again in the library finds them:

flatpak install --user flathub org.freedesktop.LinuxAudio.Plugins.LSP//25.08
Start

From the application launcher, or with:

flatpak run io.github.reverblabr.Reverblabr

The command-line tool is flatpak run --command=reverblabr-ctl io.github.reverblabr.Reverblabr. It reaches the background engine while one runs, but can't start one: the window starts the engine, and the engine stays while a session runs.

Remove
flatpak uninstall --user io.github.reverblabr.Reverblabr

Add --delete-data to remove its sessions, presets and settings as well. Recordings and virtual devices stay. The KDE runtime it brought stays too; flatpak uninstall --user --unused removes it once nothing else needs it.

The sandbox may write to your Music folder, where recordings go unless a Recorder names another folder; a folder elsewhere hasn't been tried in the Flatpak yet. It has had less use so far than the packages.

The AppImage

reverblabr-@VERSION@-x86_64.AppImage
Download the AppImage

One file that runs without being installed, on any other distribution with Plasma 6 and PipeWire 1.6. It brings everything it needs, Qt, KDE Frameworks and even its own C library, so it runs on distributions older than the ones the packages are for; it is built on Fedora 44, and each release's is started on Ubuntu 24.04 before it is published. Only your graphics drivers and PipeWire's library come from your system. It is no sandbox: it uses your folders, your virtual devices and your plugins as a package does.

What it lacks, and why

  • Auto Run at login, and timers. Both would have your account's systemd start a program inside the AppImage later, and the AppImage is there only while it runs, wherever you keep the file. The Info and Schedule tabs say so.
  • KRunner and the panel widget. Plasma looks for them in folders on your system, and the AppImage installs nothing there.
  • Virtual devices for all users. They need a helper installed as root. Devices for your own account work as in a package.
  • The manual page and the shell completions of reverblabr-ctl.
Start

Put it where you keep programs, make it executable and start it:

chmod +x ./reverblabr-@VERSION@-x86_64.AppImage
./reverblabr-@VERSION@-x86_64.AppImage

It doesn't add itself to the application launcher; an AppImage manager, such as Gear Lever, does that for you. The window starts the background engine when none is running, and the engine keeps running, and the AppImage with it, after the window is closed, while a session runs.

The command-line tool is the AppImage called by its name, through a link named reverblabr-ctl somewhere on your PATH. It reaches the background engine while one runs, but can't start one:

ln -s "$PWD"/reverblabr-@VERSION@-x86_64.AppImage ~/.local/bin/reverblabr-ctl

An AppImage runs through FUSE, which most distributions have. Without it, unpack it once with --appimage-extract and start squashfs-root/AppRun; not --appimage-extract-and-run, which deletes its copy when the window closes, while the engine is still running from it.

Remove

Delete the file. Your sessions, presets and settings are in your home folder, as with a package, and stay.

Plugins installed on your system run in the AppImage's plugin host, with its libraries; one built for a newer system than Fedora 44 may not load. Whether your desktop's help viewer finds the handbook (F1) inside the AppImage hasn't been tried yet. The AppImage is the newest way to get Reverblabr, and the one that has had the least use so far.

More than one together

Use one of them. The packages, the Flatpak and the AppImage give their background engine the same name on your desktop's bus, io.github.reverblabr.Engine. With two installed, whichever engine starts first serves both windows, so the Flatpak's or the AppImage's window can end up talking to the package's engine, or the other way round. The package and the AppImage keep their sessions in the same place; the Flatpak keeps its own.

Checking a download

The release page has SHA256SUMS beside the files. Download it to the same folder, and there:

sha256sum -c --ignore-missing SHA256SUMS

Each file you downloaded should say OK, which means it arrived whole.

Where a file comes from is shown by its build provenance attestation: a signed record, kept by GitHub, that the file was built by this repository's release workflow. The tarball, each package and the AppImage have one. With the GitHub CLI, for example:

gh attestation verify ./reverblabr-@VERSION@-1.fc$(rpm -E %fedora).x86_64.rpm --repo sorrelfox/reverblabr

SHA256SUMS has no attestation of its own, and the packages are not signed with a GPG key. GitHub's own Source code archives are not the release's tarball: they are not in SHA256SUMS and have no attestation.

What you need

  • KDE Plasma 6 on Wayland. Reverblabr is written for Plasma and nothing else. It may start on another desktop, or on Plasma under X11, but it isn't tried there.
  • PipeWire 1.6 or newer, with WirePlumber 0.5 or newer. Current distributions run both by default.
  • A 64-bit PC (x86_64, also called amd64). The packages, the Flatpak and the AppImage are built for nothing else.
  • A screen at least 768 pixels on its shorter side.
  • Real-time priority from rtkit, which Fedora and Kubuntu run by default. Without it, dropouts are likelier.
  • For some parts: KWallet, or another password store, for the Broadcast and Live Stream blocks; polkit for devices for all users; layer-shell-qt for the windows that float over other programs; an H.264 encoder for Live Stream; XWayland for the windows of plugins; KHelpCenter to read the handbook.

Updating

None of these update themselves: they don't come from a repository that dnf, apt or Flatpak follows. For a new version, download its file from the release page and install it the same way. For the Flatpak, add --reinstall to the install command. For the AppImage, put the new file in place of the old one. To hear about new versions, watch the repository's releases on GitHub.

Removing Reverblabr

Each section above says how to remove its package. Two things stay behind on purpose:

  • Virtual devices belong to PipeWire, which makes them again at every login. Delete them in the Virtual Devices window before you remove Reverblabr, or delete ~/.config/pipewire/pipewire.conf.d/90-reverblabr-virtual-devices.conf afterwards (and, as root, /etc/pipewire/pipewire.conf.d/90-reverblabr-virtual-devices-system.conf for devices for all users), then log out and back in.
  • Timers are systemd user timers in your home folder (not in the Flatpak or the AppImage, which have none). Delete them in the Schedule tab first. A timer left behind fails each time it comes round, harmlessly.

Building it yourself

reverblabr-@VERSION@.tar.xz is the source every package was built from. Reverblabr builds on Fedora 44 or newer, Kubuntu 26.04 and Debian testing in a few commands and a few minutes; Installing shows how, and Packaging what a package for another distribution needs. Run from its build folder, Reverblabr has no background engine: sessions stop with the window, and there is no Auto Run, no timers, no KRunner and no panel widget until the build is installed.

Known limitations

  • Plasma on Wayland only. Plasma on X11 and other desktops are not tried. Reverblabr is in English only so far.
  • Capturing an application, you hear it twice until you move the application to an output you aren't listening to, or use a virtual device.
  • A connection that would feed a session back into itself is refused. Name your real speakers in the Output Device.
  • Some blocks depend on the package, as the table above says.
  • A plugin that crashes leaves its block bypassed until you restart it.
  • Virtual devices stay after Reverblabr is removed, until you delete them.
  • Timers don't wake the computer. A time that passed while it slept starts nothing, unless it wakes within two minutes of it. Global shortcuts end when Reverblabr is quit from the tray, even while sessions keep running.
  • Only one Reverblabr runs per desktop.
  • Live Stream needs an H.264 encoder on the computer. On Fedora that is openh264, or the full FFmpeg from RPM Fusion. Which encoder the Flatpak finds hasn't been tried yet.
  • The windows that float over other programs need layer-shell-qt. On X11 they stay above the main window only.
  • The Model block is Beta. No models are included, Fedora's ONNX Runtime runs it on the processor only, and a voice adds about 390 ms of delay.
  • The Hearing blocks are not a medical device, and their limits are digital, not a level at your ear. Frequency Raising is experimental in parts, and Sudden Sounds' thresholds are provisional. Speech Now, Voice Gauge and Sound Side can be wrong.
  • A running session isn't listed in the Plasma audio applet, only in PipeWire's own tools.
  • A Bluetooth headset drops to hands-free sound while anything records from it.
  • The Flatpak lacks what its section lists, shares the engine's name with the packages, and has to be killed and started again after PipeWire restarts.
  • The AppImage lacks what its section lists, shares the engine's name with the packages, and is about 150 MB.
  • Nothing updates itself. Download each new version from the release page.

Found something else? Open an issue, say which package you installed, and paste what Copy Diagnostics on the Info tab gives you.
